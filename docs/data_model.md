# Data Model

This project is based on two main tables that simulate the behaviour of users in a fintech application.

---

# users

Each row represents a unique user registered on the platform.

| Column | Type | Description |
|--------|------|-------------|
| user_id | INTEGER | Unique identifier of the user |
| age | INTEGER | User age |
| country | TEXT | User country |
| device | TEXT | Mobile device used (Android / iPhone) |
| acquisition_channel | TEXT | Marketing channel through which the user was acquired |
| registration_date | DATE | Registration date |
| income_level | INTEGER | Estimated monthly income (€) |
| occupation | TEXT | User occupation |
| plan | TEXT | Subscription plan (Basic, Plus, Pro, Elite) |

Primary Key:

```
user_id
```

---

# events

Each row represents an event generated by a user during the onboarding or product usage journey.

| Column | Type | Description |
|--------|------|-------------|
| user_id | INTEGER | User identifier |
| event | TEXT | Event name |
| timestamp | DATETIME | Event timestamp |
| deposit_amount | REAL | Deposit amount (only for first_deposit events, NULL otherwise) |

---


# Event Flow

Users can generate the following events in chronological order:

1. sign_up
2. kyc_completed
3. first_deposit
4. card_ordered
5. app_opened
6. first_payment
7. investment_started

Not every user reaches the final step of the funnel.
